# QA 기록: 녹음 일시정지·이어서 녹음, 저장 전 음성 변환

- 날짜: 2026-10-28
- 방식: 작성 흐름과 분리된 서브에이전트가 시니어 개발자 관점에서 코드 리뷰 (CLAUDE.md 2번 규칙), 지적 사항 수정 후 같은 리뷰어가 재검토
- 대상 기능
  1. 녹음 중 일시정지/계속하기, 녹음을 마친 뒤 같은 파일에 이어서 녹음
  2. 녹음을 마치면 저장 전에 바로 음성을 글로 옮겨 화면에 표시
  3. 일시정지 버튼과 "다 했어요" 버튼 높이 통일
- 대상 파일 (`AOS/app/src/main/java/com/vibediary/app/` 기준)
  - `capture/AudioRecorder.kt`
  - `ui/newentry/NewEntryViewModel.kt`
  - `ui/newentry/NewEntryScreen.kt`
  - `ai/Transcriber.kt`
  - 함께 확인: `ai/AnalysisWorker.kt`

> 줄 번호는 리뷰 당시 기준이라 이후 수정으로 달라졌습니다. 아래는 함수와 상황 기준으로 적었습니다.

## 1차 QA: 일시정지·이어서 녹음 최초 구현

빌드: 통과 (오류·경고 없음)

### Critical

| # | 문제 | 발생 상황 | 수정 내용 |
|---|---|---|---|
| C1 | **일시정지 상태에서 녹음을 끝내면 WAV 헤더가 기록되지 않음.** 일시정지 중 녹음 루프는 `delay(50)`에서 대기하는데, `stop()`의 `cancelAndJoin()`이 이 `delay`를 취소하면서 헤더 쓰는 줄을 건너뜀. | 일시정지 → "다 했어요" (흔한 사용 흐름). 새 녹음은 헤더가 0으로 남아 상세 화면에서 재생 불가. 이어서 녹음한 경우에는 헤더가 예전 길이로 남아 뒤에 붙인 부분이 사라짐. | `writeWav()`에서 헤더 기록을 `finally` 블록으로 옮겨 취소되어도 반드시 기록. |

### Major

| # | 문제 | 발생 상황 | 수정 내용 |
|---|---|---|---|
| M1 | **`read()` 실패 시 무한 루프.** 오류 코드(음수)가 나와도 아무 처리 없이 계속 돌아 CPU를 쓰고 타이머만 멈춤. `resume()`의 `startRecording()`이 조용히 실패해도 같은 상태. | 통화 등으로 마이크를 빼앗긴 경우 | 녹음 중 `read()`가 음수면 `hasFailed` 표시 후 루프 종료. 일시정지 중 생기는 오류(멈춘 녹음기를 읽는 경우)는 무시. ViewModel이 `hasFailed`를 감지하면 녹음을 멈추고 안내 문구 표시. |
| M2 | **"다 했어요" 처리 중 버튼이 계속 눌림.** `stop()`이 끝날 때까지 `recording`이 true라서 일시정지·완료를 다시 누를 수 있음. | 완료를 두 번 누르면 `release()` 중복 호출. 해제된 녹음기에 `startRecording()`이 불리면 `IllegalStateException`으로 앱 종료. | ViewModel에 `stopping` 상태를 추가하고, 처리 중에는 일시정지·완료 버튼 비활성화. `stop()`은 녹음기 참조를 먼저 비워 두 번 불려도 안전하게 함. |
| M3 | **녹음 시작 실패 시 앱 종료 또는 상태 꼬임.** 녹음기를 필드에 먼저 넣은 뒤 `startRecording()`을 호출해서, 초기화 실패(마이크 사용 중 등) 시 메인 스레드에서 예외 발생. | 다른 앱이 마이크를 쓰는 중에 녹음 시작 | `tryStartCapturing()` 헬퍼로 `STATE_INITIALIZED`와 `RECORDSTATE_RECORDING`을 확인. 성공했을 때만 필드에 저장. `start()`와 `resume()`은 성공 여부(Boolean)를 반환하고, 실패하면 "지금은 마이크를 쓸 수 없어요…" 안내. |

### Minor

| # | 문제 | 처리 |
|---|---|---|
| m1 | 일시정지를 누르는 순간 읽던 버퍼(수십 ms)가 버려짐 | 의도된 동작(대부분 버튼 누르는 소리)이라 유지. 이유를 주석으로 남김. |
| m2 | 헤더의 `.toInt()`가 2GB(약 18시간) 넘으면 오버플로 | 현실적으로 발생하지 않아 유지. |
| m3 | 이어서 녹음 시 파일 길이를 그대로 믿음 | 앱이 만든 파일만 다루므로 문제없음. 오히려 깨진 헤더도 복구됨. |
| m4 | 일시정지 중 ViewModel이 정리될 때 | 안전함 확인 (임시 파일은 어차피 삭제). |

### Nit (클린 코드)

| 지적 | 수정 |
|---|---|
| `NewEntryScreen.kt`의 쓰지 않는 import (`mutableLongStateOf`, `delay`): 예전 타이머의 흔적 | 삭제 |
| 쓰이지 않는 `AudioRecorder.isRecording` | 삭제 |
| 매직 넘버 `delay(50)`, `delay(90)`, `minBuf * 4`, `SAMPLE_RATE * 2` 중복 | `PAUSE_POLL_MS`, `LEVEL_POLL_MS`, `BUFFER_MULTIPLIER`, `BYTES_PER_SECOND` 상수로 정리 |
| `java.io.File` 전체 이름 사용 | import된 `File` 사용 |
| 모호한 함수 이름 `begin` | `startCapture`로 변경 |
| 축약 변수명 (`rec`, `raf`, `buf`, `n`) | `recorder`, `file`, `chunk`, `bytesRead` 등으로 변경 |
| `runCatching { stop() }`에 이유 주석 없음 | `stopQuietly()`로 묶고 이유 주석 추가 |

## 2차 QA: 1차 수정 재검토

빌드: 통과. 1차 지적 사항은 모두 해결 확인. Critical·Major 없음.

| # | 등급 | 문제 | 발생 상황 | 수정 내용 |
|---|---|---|---|---|
| 1 | Minor | **이어서 녹음 실패 시 녹음 전체가 멈추고 안내가 두 번 뜸.** `resume()` 실패가 `hasFailed`를 세워서 ViewModel이 녹음을 종료함. | 일시정지 → 통화 → 통화 중에 계속 누름: "마이크 쓸 수 없음"과 "마이크 끊김"이 연달아 뜨고 녹음 종료. 통화가 끝난 뒤 다시 시도할 수 없음. | `resume()` 실패는 `hasFailed`를 세우지 않고 일시정지 상태 유지. 통화가 끝난 뒤 다시 누를 수 있음. |

| 4 | Nit | `catch (e: IllegalStateException)`에서 `e`를 쓰지 않음 | — | 왜 무시하는지 주석 추가 |

## 3차 QA: 저장 전 음성 변환 표시

빌드: 통과. Critical·Major 없음.

### 확인된 정상 동작
- **취소 처리:** 이어서 녹음, 녹음 삭제, 변환 중 저장, 화면 나가기 모두 변환 작업을 취소함. 음성인식기는 `Transcriber`의 취소 처리에서 해제되어 누수가 없음.
- **늦게 온 결과:** 취소된 뒤 도착한 결과는 버려져서 상태를 덮어쓰지 않음.
- **파일 완결성:** `stop()`이 녹음 작업을 기다린 뒤(헤더 기록 포함) 변환을 시작하므로 항상 완전한 파일을 읽음.
- **백그라운드 분석과의 일관성:** 말소리 없음(`""`)은 그대로 저장되어 백그라운드 분석이 다시 하지 않음. 변환 실패나 중단(`null`)은 저장 후 백그라운드에서 다시 변환함.

### 지적 사항과 수정

| # | 등급 | 문제 | 수정 내용 |
|---|---|---|---|
| 1 | Minor | **안내 문구가 이어 붙여져 어색함.** 실패 사유 뒤에 고정 문장을 붙여 "…'다시 분석'을 눌러주세요 저장하면 나중에 다시 옮겨 볼게요."처럼 두 문장이 붙음. 이 화면에 없는 '다시 분석' 버튼을 안내함. Android 12 이하에서는 절대 될 수 없는데 "나중에 다시 옮겨 볼게요"라고 약속함. (에뮬레이터에서도 실제로 확인) | `Transcriber.Result.Unavailable`에 원인 종류 `Problem`(`UNSUPPORTED`, `LANGUAGE_PACK`, `TEMPORARY`)을 추가. 새 기록 화면은 종류별로 이 화면에 맞는 문구를 보여 줌. 저장된 기록의 상세 화면용 문구(`reason`)는 따로 유지. |
| 2 | Minor | **음성인식 엔진이 바쁠 때(오류 코드 8) "음성인식 오류 (코드 8)"이 그대로 노출됨.** 직전 기록을 백그라운드에서 분석하는 중이면 발생 가능. | 일시적 실패(`TEMPORARY`)는 1.5초 뒤 한 번 자동 재시도. 그래도 실패하면 "지금은 글로 옮기지 못했어요. 저장하면 다시 옮겨 볼게요." 표시. 원시 오류 코드 문구도 순화. |
| 3 | Nit | `Transcriber`에 `SAMPLE_RATE * 2`, `30_000` 매직 넘버 (이번 변경 이전부터 있던 코드) | `AudioRecorder.BYTES_PER_SECOND`를 공개해 재사용. `TIMEOUT_CLIP_FACTOR`, `TIMEOUT_EXTRA_MS` 상수로 정리. |

## 아직 확인하지 못한 것
- **실제 폰에서 저장 전 변환 결과가 글로 나오는지:** 에뮬레이터에는 한국어 언어팩이 없음.
- **마이크를 빼앗기는 상황:** 통화 중 계속하기, 녹음 중 다른 앱이 마이크 사용.
- **저장공간 부족 시 안내 동작:** 직접 재현하지 않음.
- **음성인식 엔진이 바쁠 때의 자동 재시도:** 직접 재현하지 않음.
