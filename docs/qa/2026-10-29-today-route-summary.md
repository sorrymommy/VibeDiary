# QA 기록: 홈 "오늘의 노선" 요약 카드

- 날짜: 2026-10-29
- 계기: 사용자 요청
  1. 정류장 5개까지는 가운데 정렬
  2. 6개부터는 옆으로 스크롤
  3. 다음 정류장으로 이어지는 선을 미리 그리지 않음. 1개면 검은 점 하나만, 2개면 흰 점과 검은 점을 잇는 초록 선만 표시
- 대상 파일: `AOS/app/src/main/java/com/vibediary/app/ui/home/HomeScreen.kt` (`RouteSummary`, `RouteStop`, `StationRow`의 선 굵기)

## 수정 내용
- 기존에는 두 가지로 나뉘어 있었습니다.
  - `SpreadRoute` (4개 이하): 카드 폭 전체에 퍼뜨림. 1개일 때도 오른쪽으로 짧은 선을 그림.
  - `ScrollingRoute` (5개 이상)
- 이 둘을 `RouteSummary` 하나와 `RouteStop`으로 합쳤습니다.
  - 정류장 한 칸의 폭은 카드의 1/5(`VISIBLE_STOPS = 5`)로 고정합니다.
  - 5개 이하는 내용 폭만큼만 차지해 가운데에 놓이고, 6개 이상은 가로로 스크롤됩니다.
- 선은 각 정류장에서 이웃 쪽으로만 그립니다. 첫 정류장 왼쪽과 마지막 정류장 오른쪽에는 선이 없습니다.

## 1차 QA

정상 확인:
- `horizontalScroll` 안에서도 5개 이하일 때 가운데 정렬이 실제로 됩니다.
- 1개일 때는 선 없이 검은 점만, 2개일 때는 두 점 사이에만 선이 그려집니다.
- 정류장이 6개에서 5개로 줄어도 스크롤 위치가 어긋나지 않습니다.
- 지운 함수의 흔적이나 쓰지 않는 상수가 없습니다.

|---|---|---|---|---|

## 2차 QA

정상 확인:
- `reverseScrolling`은 스크롤 방향만 바꿉니다. 화면 순서는 그대로 왼쪽(오래된 정류장)→오른쪽(최신)입니다.
- 5개 이하에서는 가운데 정렬이 유지됩니다.
- px 내림으로 5칸의 합이 카드 폭을 넘지 않습니다.
- 1개, 2개일 때 선 그리기가 맞습니다.
- 쓰지 않는 import가 없습니다.

| # | 등급 | 문제 | 발생 상황 | 수정 내용 |
|---|---|---|---|---|
| 1 | Minor | 옛 정류장 쪽으로 스크롤해 둔 상태에서 새 정류장이 추가되면, 최신 정류장이 보이지 않고 보이는 구간이 한 칸 밀림 | 스크롤 위치가 "끝에서 떨어진 거리"로 기억되기 때문 | 스크롤 상태를 `remember(today.size) { ScrollState(initial = 0) }`로 바꿔, 정류장 수가 바뀌면 최신 정류장으로 돌아가게 함 |
| 2 | Nit | 화면 회전이나 목록 스크롤 후 다시 보면 최신 위치로 초기화됨 | — | **의도된 동작.** 요약 카드는 늘 최신 정류장을 먼저 보여 줌 |
| 3 | Nit | 파일 import 순서가 섞여 있음 | — | **수정하지 않음.** 이번 변경 전부터 있던 상태이고 동작과 무관 |
| 4 | Nit | `StationRow`의 `12.dp`, `28.dp` 등 이름 없는 숫자 | — | **수정하지 않음.** 이번 변경 범위 밖 |

## 아직 확인하지 못한 것
- 정확히 5개일 때 스크롤이 생기지 않는지는 에뮬레이터에서 직접 보지 않았습니다. 2~4개는 같은 방식이고, 5개는 계산상 카드 폭 이하가 됩니다.
- 홈 화면이 보이는 동안 동기화로 정류장이 늘어나는 경우
- 좁은 화면(320dp)과 큰 글꼴 설정
- 실제 폰(S23)의 화면
